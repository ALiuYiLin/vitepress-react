# 在 Markdown 中使用 React

需要组件 / 表达式的页面写成 **`.mdx`** 文件,由 mdx 内核编译:整份文件就是一个 React 模块,`import` / `export` 与 JSX 可以直接写在文件里。正文中普通文本是字面量,**单层 `{…}` 一律按 JSX 表达式求值**,与在 React 组件里写 JSX 是同一套语义。

给页面加入动态能力只有两步:

1. 在**模块顶层**(frontmatter 之后)用 `import` / `export` 声明组件、常量或数据;
2. 在正文写 `{expr}` 求值表达式,或直接放 `<组件 />`。

完整的规则清单(哪些写法会报错、attrs 的各个位置等)见[Markdown 中的 React 规则](./md-react-rules);给页面写只作用于本页的样式见[md 页面 scoped 样式](./md-scoped-demo)。

::: tip 正文的三个基本事实
- **普通文本与 HTML 是字面量**,原样渲染;
- **正文里的 `{…}` 按 JSX 表达式求值**——引用顶层绑定、做字面量运算、跑任意 JS 都行;
- **代码块与行内代码永远是字面量**,里面的 `{…}` 不会被求值,也不需要任何转义。
:::

## 正文表达式

在正文任意位置写 `{expr}`:

- 引用模块顶层绑定:`{siteName}`、`{frontmatter.title}`、`{fmt(page.title)}`;
- 字面量运算:`{1 + 1}`、`{'hi'.toUpperCase()}`;
- 任意 JS 表达式:`{items.length ? '有' : '无'}`。

例如正文里写 `{1 + 1}` 会渲染成 `2`。

想在**正文里显示花括号本身**(例如展示模板语法),把内容放进行内代码或代码块即可:`` `{x}` ``、`` `{1 + 1}` `` 都按字面显示。不要在正文里用转义花括号 `\{…\}` 显示字面量——在 mdx 内核里 `\{…\}` 是 **attrs(属性)语法**的书写形态,另有用途(见[给元素加类与锚点](./md-scoped-demo#adding-classes-and-anchors))。

写错即报错,与 JSX 一致:

- `{统计}` 引用了未定义的变量 → 运行时 `ReferenceError`;
- `{#foo}` 这类写法会被当作表达式解析 → 编译错误(给元素加 id / class 请用 attrs)。

## 模块绑定:import / export / frontmatter \{#module-bindings\}

每份 `.mdx` 都是一个模块。文件顶层(frontmatter 之后)可以直接写 `import` 与 `export`,这是正文之外唯一能“放代码”的位置:

- **`import`**——引入组件、常量、npm 包、data loader 的具名导出等;相对路径以页面文件的位置为基准;
- **`export const` / `export function`**——导出常量与组件,成为模块顶层绑定,正文 `{expr}` 与 JSX 均可引用;
- **`frontmatter`**——页面顶部 YAML 自动导出为模块变量 `frontmatter`,正文直接写 `{frontmatter.xxx}` 即可,无需 import。

一份完整的页面源码示例:

````mdx
---
title: 我的页面
---

import { useState } from 'react'
import ComponentInHeader from '../../components/ComponentInHeader.tsx'

export const siteName = 'vitepress-react'

export function Note() {
  return <strong>这是 export 导出的组件</strong>
}

本页标题来自 frontmatter:{frontmatter.title}

本站名:{siteName}

<ComponentInHeader />
<Note />
````

要点:

- 需要被正文引用的常量 / 组件,要么 `import` 进来、要么在本文件 `export`——正文只能引用**模块顶层绑定**,不要写不带 `export` 的裸顶层语句;
- `frontmatter` 无需 import,也不要自行声明同名导出。

## 组件与 hooks:让内容交互

正文本身不能持有状态或调用 hooks。需要交互(状态、副作用、事件)时,把 UI 封装成**组件并导出**,再在正文放 `<组件 />`:

````mdx
import { useState } from 'react'

export function Counter() {
  const [count, setCount] = useState(0)
  return (
    <button onClick={() => setCount(count + 1)}>
      count: {count}
    </button>
  )
}

<Counter />
````

保存为 `.mdx` 页面后,正文会渲染出一个可点击的按钮。规则:

- **hooks(`useState` / `useEffect` / `useData` / `useRoute`…)只能在组件函数体内调用**,不能出现在文件顶层或正文;页面要状态,就把它封装成组件——每个组件各自持有自己的 state;
- 组件名必须 **PascalCase**(React 依靠首字母大小写区分组件与原生元素),且是模块顶层绑定(import 或 export 而来);
- `export function Xxx() {}` 与 `export const Xxx = () => …` 两种写法皆可。

### 多行 JSX 与列表渲染

跨多行、含 JS 表达式的 JSX(例如 `map` 列表)直接写在正文,与相邻段落之间留空行:

````mdx
export const items = [
  { id: 1, name: 'Alpha' },
  { id: 2, name: 'Beta' },
  { id: 3, name: 'Gamma' }
]

<ul>
  {items.map((item) => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
````

`key` 是 React 列表渲染要求的属性,别忘了写。

### 行内 JSX 与 JSX 属性

行内小元素(`<b>…</b>`、`<Badge … />`)可以与文字在同一段落;**独立成行的块级 JSX**(`<ul>`、`<div>`、组件等)与前后文本之间用空行隔开。JSX 属性按 React 规则写:`class` → `className`,`style` → 对象,事件 → 驼峰函数 `onClick`;`{expr}` 照常求值。

## 页面数据:useData / useRoute

需要把站点/页面数据交进组件逻辑(例如作为 `useEffect` 的依赖)、或读取 `page` / `params` 字段时,用 `useData()`(返回 `site` / `page` / `frontmatter` / `params` 等)与 `useRoute()`——它们是 React hook,只能在**组件函数体内**调用:

````mdx
import { useData } from '@10coding/vitepress-react'

export function PageTitle() {
  const { frontmatter } = useData()
  return <h2>{frontmatter.title}</h2>
}

<PageTitle />
````

页面自身的静态 frontmatter 用模块变量 `{frontmatter.xxx}` 即可,不必经过 hook(见[模块绑定](#module-bindings));可用字段与其余 API 见[运行时 API](../reference/runtime-api#usedata),路由参数见[路由参数](./routing#accessing-params-in-page)。

## 引入并使用组件 \{#using-components\}

如果组件只被少数页面使用,在页面模块顶层显式 import(还能获得正确的代码分割):

````mdx
---
title: Docs
---

import CustomComponent from '../../components/CustomComponent.tsx'

# Docs

这是用自定义组件的 .mdx 页面:

<CustomComponent />
````

绝大多数页面都要用的组件,放在自定义主题/布局层统一包装与注入,见[扩展默认主题](./extending-default-theme)。

默认主题也导出可直接用的组件(`VPBadge`、`VPTeamMembers` 等,统一从 `@10coding/vitepress-react/theme` 导入),import 后即可在正文使用:

````mdx
import { VPBadge } from '@10coding/vitepress-react/theme'

<VPBadge type="tip" text="new" />
````

::: warning 组件名必须是 PascalCase
自定义组件标签名必须 **PascalCase** 且是模块顶层绑定(通过 `import` 引入或 `export` 定义),否则不会被当作组件解析。
:::

### 标题里的组件

标题行可以嵌组件,但解析出的标题(大纲、侧边目录)只取**纯文本**:

| Markdown                                        | 解析出的标题 |
| ----------------------------------------------- | ------------ |
| `# 文档 <Badge type="info" text="new" />`       | `文档`       |
| `# 文档 \`<Badge/>\``                           | `文档 <Badge/>` |

行内代码里的内容不会被解析成组件。

## 代码块与行内代码

代码块天然是字面量,不需要任何包装:想展示 `{1 + 1}`、模板片段等,直接放进代码块即可,内容永不求值。

**输入**

````md
```text
Hello {1 + 1}
```
````

**输出**

```text
Hello {1 + 1}
```

## 样式与客户端专属内容 \{#styles-and-client-only\}

- **全局样式**:普通 CSS 文件在模块顶层 `import './style.css'`,交给 Vite css 管线;
- **页面级 scoped 样式**:把规则放进独立的 `*.scoped.css` 文件,顶层 `import './page.scoped.css'`。编译后选择器会带 `[data-v-{hash}]`,页面正文 DOM 也自动带上同一属性,规则只命中当前页面。需要先在站点配置开启 `themeConfig.markdownScopedCss: true` 并注册 `jsxScopedVitePlugin()`(本示例站点已开启);用法与实时示例见 [md 页面 scoped 样式](./md-scoped-demo);
- **mdx 正文里不要写 `<style>` / `<style scoped>` 块**——它会被当作 JSX 解析而编译失败;
- 组件文件内部的局部样式按 Vite 常规使用(CSS Modules、样式文件、CSS 预处理器等)。

### 只在浏览器渲染的内容

组件在 SSR 与浏览器都会渲染。只在浏览器出现的内容(读取 `window` / `document`、用 portal 挂到 `body`)推荐**自门控**的写法:用 `useEffect` 标记已挂载,挂载前返回 `null`:

````mdx
import { useEffect, useState } from 'react'

export function Toast() {
  const [mounted, setMounted] = useState(false)
  useEffect(() => setMounted(true), [])
  if (!mounted) return null
  return <div className="toast">hello</div>
}

<Toast />
````

也可以用 `<ClientOnly>` 包裹只在客户端渲染的子树(见[运行时 API](../reference/runtime-api#clientonly)):

````mdx
import { ClientOnly } from '@10coding/vitepress-react'

<ClientOnly>
  <Toast />
</ClientOnly>
````

页面上的所有组件都要兼容 SSR——组件在服务端抛错会让构建失败,详见[SSR 兼容性](./ssr-compat)。
