# Markdown 中的 React 规则

本文是[在 Markdown 中使用 React](./using-react) 的“规则手册”:`.mdx` 页面由 mdx 内核编译,整份文件是一个 React 模块——`import` / `export` 与 JSX 直接写在文件里,正文普通文本是字面量,单层 `{…}` 按 JSX 表达式求值。每条规则先讲规则,再给可直接照抄的示例(代码块),部分规则附本页实时渲染——本页正文就是用同一套规则写出来的。

::: tip 三条核心规则
1. **文档即模块**:`import` / `export` 与 JSX 直接书写在 `.mdx` 文件里;正文可引用的范围 = 模块顶层绑定;
2. **hooks 只能进组件函数体**:`useState` / `useEffect` / `useData` / `useRoute` 都不能出现在文件顶层或正文;页面要状态就把 UI 封装成组件,以 `<Xxx />` 挂到正文;
3. **字面花括号用代码块 / 行内代码**:正文里任何未转义的 `{…}` 都会被当作表达式求值,想显示 `{x}` 本身请放进代码块或行内代码。
:::

## 速查表

| 写法 / 位置 | 处理结果 |
| --- | --- |
| 普通正文文字(不含 `{…}`) | 字面文本,原样渲染 |
| 正文 `{expr}` | 按 **JSX 表达式**求值(React 语义):引用顶层绑定、纯字面量、任意 JS 都行;未定义引用 → 运行时 `ReferenceError`,语法错误 → 编译报错 |
| 行内代码 / 代码块里的 `{…}` | 字面量,永不求值,可放心展示模板或示例 |
| 顶层 `import` | 模块导入,正文与组件都可引用 |
| 顶层 `export const` / `export function` | 声明组件、常量与数据;组件以 `<Xxx />` 使用,常量以 `{name}` 引用 |
| hooks | 只能在**组件函数体内**调用;文件顶层与正文中都不允许 |
| YAML frontmatter | 自动导出为模块变量 `frontmatter`,正文可写 `{frontmatter.xxx}` |
| 独立成行的 `<标签>…</标签>` / `<组件 />` | 按 JSX 编译(块级 JSX 与相邻文本之间留空行) |
| 段落里的 `<b>`、`<Badge … />` 等 | 行内 JSX,同样生效 |
| 标题行尾 / 块后独立行的 `\{…\}` | **attrs 语法**(转义书写形态):`\{#id\}` 锚点、`\{.cls\}` 加类,作用于所在标题或紧邻其前的块(见 §4 与 [md-scoped-demo](./md-scoped-demo)) |
| `::: tip … :::` 等容器、`> [!NOTE]` 提示 | 照常渲染(见 §4) |
| mdx 正文里的 `<style>` 块 | 会被当作 JSX 解析而编译失败;样式请走外部文件(见 §4) |

**JSX 属性按 React 规则写**:`class` → `className`,`style` → 对象,事件 → 驼峰函数(`onClick`);自定义组件用 PascalCase 命名,且必须先 import 或在本文件 export。

## 1. 正文 `{expr}` 一律求值

- **一律求值**:正文里每对 `{…}` 都是 JSX 表达式——引用模块顶层绑定(`{items.length}`、`{fmt(x)}`)、纯字面量(`{1 + 1}`、`{'hi'}`)或任意 JS 表达式;
- **可引用的范围 = 模块顶层绑定**:import 的符号与 export 出的常量 / 函数 / 组件;正文无法引用“页面隐式状态”——要状态就封装成组件(§3);
- **展示字面花括号**:放进行内代码或代码块即可,内容永不求值(`` `{x}` ``、`` `{1 + 1}` `` 都按字面显示);不要用 `\{…\}` 去“转义字面花括号”——那是 attrs 语法的书写形态(§4);
- **写错即报错**(与 JSX 一致):`{统计}` 引用未定义变量 → 运行时 `ReferenceError`;`{#foo}` 这类写法会被当作表达式解析 → 编译报错(元素的 id / class 请用 attrs,见 §4)。

**示例(可直接照抄到 .mdx)**

```mdx
export const version = '1.2.3'

当前版本:{version};1 + 1 = {1 + 1};字面花括号用行内代码 `{x}` 即可
```

上面的正文会渲染成:**当前版本:1.2.3;1 + 1 = 2;字面花括号用行内代码 `{x}` 即可**。

**本页实时渲染**(这一行就是真实表达式)

1 + 1 = {1 + 1}

::: tip 想展示字面花括号?
放进行内代码或代码块即可,例如 `{x}`、`{1 + 1}` 都按字面显示。正文里任何未转义的 `{…}` 都会被当作表达式求值;`\{…\}` 是 attrs 属性语法,不要用它显示字面量。
:::

## 2. import / export:定义模块绑定

- `import … from '…'` 写在模块顶层,习惯放在 frontmatter 之后、正文之前;正文与页面组件共享同一份模块作用域;
- 页面内要复用的数据、常量、函数用 **export** 声明(`export const items = […]`),这是正文能引用的“自建绑定”方式;
- import / export 是真实 ESM:相对路径组件、npm 包、data loader 都可以直接导入。

**示例**

```mdx
import CustomWidget from '../../components/CustomWidget.tsx'

export const tagline = 'Docs with React'

自定义组件:<CustomWidget label={tagline} />
```

需要构建期数据时,像普通 ESM 一样导入 data loader 的具名导出:

```mdx
import { data as posts } from './posts.data.js'
```

然后在正文或组件里用 `{posts.length}`、`posts.map(...)` 消费它(多行列表的写法见 §3)。

### frontmatter 自动导出

页面顶部 YAML frontmatter 自动导出为模块变量 `frontmatter`,正文直接 `{frontmatter.xxx}` 引用:

```mdx
---
title: Docs with VitePress
editLink: true
---

本页标题是:{frontmatter.title},是否可编辑:{frontmatter.editLink ? '是' : '否'}
```

站点级数据(`site` / `theme` / `page` / `params`)由 `useData()` 提供,但它是 hook,只能放进组件里(见 §3);页面自身的 frontmatter 用上面的 `frontmatter` 变量即可。

## 3. 组件定义与 JSX(hooks 的归宿)

正文本身不能持有状态。要让一段内容可交互,把它**定义成一个组件**(具名导出),再以 JSX 挂到正文:

**示例:带 hooks 的交互组件**

```mdx
import { useState } from 'react'

export function Counter() {
  const [count, setCount] = useState(0)
  return (
    <button onClick={() => setCount(count + 1)}>
      count: {count}
    </button>
  )
}

<Counter />
```

- `import` 写在最前;组件用 `export function Xxx() {}`(或 `export const Xxx = () => …`)定义;
- hooks 写在**组件函数体内**,不能出现在正文或模块顶层;状态、副作用、事件都归组件内部,每个组件各自持有自己的 state;
- 需要站点数据时同理——把 `useData()` 封装进组件(主题组件、`.tsx` 组件文件、本文件内定义的组件都行):

```mdx
import { useData } from '@10coding/vitepress-react'

export function FooterCopyright() {
  const { theme } = useData()
  return <p>页脚版权:{theme.footer.copyright}</p>
}

<FooterCopyright />
```

- 使用组件前确保已 import 或在本文件 export;PascalCase 的未知标签会因找不到组件而在运行时报错。

**多行 JSX / 列表:直接写在正文**

```mdx
export const items = [
  { id: 1, name: 'Alpha' },
  { id: 2, name: 'Beta' },
  { id: 3, name: 'Gamma' }
]

<ul>
  {items.map((item) => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
```

- **块级 JSX**(独立成行的 `<ul>`、组件等)与前后文本之间用空行隔开;行内小元素(`<b>`、`<Badge … />`)可以与文字在同一段落;
- JSX 属性按 React 写:`class` → `className`、`style` → 对象、事件 → `onClick` 等驼峰函数;`key` 是列表渲染必需的属性;
- 浏览器专属副作用(读写 `window` / `document`)放在组件内的 `useEffect` 或客户端专属组件里,保证 SSR 安全(见 §5)。

**本页实时渲染**(同一规则真实写在本文:`export function LiveCounter()` + 挂载)

export function LiveCounter() {
  const [count, setCount] = useState(0)
  return (
    <button
      style={{ border: '1px solid var(--vp-c-brand-1)', borderRadius: 8, padding: '4px 14px', cursor: 'pointer' }}
      onClick={() => setCount(count + 1)}
    >
      count: {count}
    </button>
  )
}

<LiveCounter />

## 4. 标题、attrs、容器与样式

### 标题

- ATX 标题行与正文同一套 mdx 文本规则:行内组件与 `{expr}` 都可以写(例如 `## 标题 <Badge type="tip" text="new" />`);
- 页面大纲(headers)在编译期取标题**纯文本**,不含组件渲染输出与表达式求值结果,可见标题与大纲因此可能不完全一致;
- 标题行尾可以写 attrs 固定锚点 / 类(mdx 内核 attrs 书写为 `\{…\}`,本节标题 `### attrs:给元素加 id / class \{#attrs\}` 即如此):`## 标题 \{#my-anchor\}`。attrs 编译期生效,标题带显式 id / class,纯文本不含残字。

### attrs:给元素加 id / class \{#attrs\}

attrs 作用于**元素本身**,书写为转义形态 `\{…\}`(避免被当作 JSX 表达式):

| 位置 | 写法 | 作用 |
| --- | --- | --- |
| 标题行尾 | `## 标题 \{#my-anchor\}`、`## 标题 \{.my-cls\}` | 给该标题加 id / class(固定锚点) |
| 块级元素之后独立一行 | `\{.my-card\}` | 作用于**紧邻其前的块**(段落、列表、容器等) |

```mdx
## 章节标题 \{#chapter-1\}

这一段在下一行 attrs 生效后会被加上 `my-card` 类。

\{.my-card\}
```

页面级 scoped 样式配合 attrs 给正文元素加类使用,实时演示见[md 页面 scoped 样式](./md-scoped-demo)。

### 容器

默认容器照常可用,标题写在与 `:::` 同行、内容与容器行之间用空行隔开:

```mdx
::: tip 提示
内容……
:::

::: details 查看详情
默认收起;写 `((open))` 默认展开。
:::
```

`tip` / `info` / `warning` / `danger` / `details` 等默认容器,以及 `> [!NOTE]`、`> [!WARNING]` 这类 GitHub 风格提示都可用;更多 Markdown 扩展语法(表格、任务列表、代码分组、数学公式等)见[Markdown 扩展](./markdown)。

### 样式

- 样式文件用普通 ESM 导入,写在模块顶层:`import './page.css'`(全局样式同理);
- 页面级 **scoped 样式**:把规则放进外部 `*.scoped.css` 文件,同样顶层导入:`import './page.scoped.css'`——选择器会带 `[data-v-{hash}]` 只命中本页。开启步骤与作用域语义见 [md 页面 scoped 样式](./md-scoped-demo);
- mdx 正文里不要写内联 `<style>` / `<style scoped>` 块:它们会被当作 JSX 解析而编译失败。组件文件内部的局部样式用 CSS Modules、样式文件或内联样式。

## 5. 常见错误与 SSR

| 场景 | 结果 / 处理 |
| --- | --- |
| 正文 `{统计}`(未定义引用) | 运行时 `ReferenceError` |
| 正文 `{#foo}`、`{1 +` 等非法表达式 | mdx 编译报错,错误信息定位到 `.mdx` 的行列;id / class 请用 attrs 写法 |
| 使用了未 import / export 的 PascalCase 标签 | 运行时找不到该组件;先 `import` 或在本文件 `export` |
| 在正文或模块顶层调用 hooks / 写普通 JS 语句 | 非法:封装成组件(§3),或移进组件函数体 |
| mdx 正文写 `<style>` / `<style scoped>` | 编译失败;样式放外部文件,页面级用 `*.scoped.css`(§4) |
| 想展示 `{…}` / 模板示例本身 | 放进行内代码或代码块,永不求值 |

::: warning SSR 兼容性
所有 live 代码都要兼容 SSR:避免在组件体或模块顶层读写 `window` / `document`;浏览器专属逻辑放 `useEffect`、客户端专属组件或 `ClientOnly` 里(参见[SSR 兼容性](./ssr-compat))。
:::
