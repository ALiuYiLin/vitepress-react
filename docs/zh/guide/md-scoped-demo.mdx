# md 页面 scoped 样式

页面级 scoped 样式把样式**只作用于当前页面**:样式编译后选择器会追加 `[data-v-{hash}]`,页面正文的 DOM 也自动带上同一属性——规则只命中本页,不会泄漏到其它页面。`{hash}` 由页面文件的绝对路径生成,每一页各不相同;同一页面的多个 scoped 文件共用同一个 hash。

使用流程只有两步:**把样式写进独立的 `*.scoped.css` 文件,再在页面模块顶层 import 它**。

::: tip 两种样式的分工
- **全局样式**:普通 CSS 文件(不以 `.scoped.` 命名)顶层 `import './style.css'` —— 交给 Vite css 管线,作用于全局;
- **页面级 scoped 样式**:`*.scoped.css` 文件顶层 `import './page.scoped.css'` —— 自动 scope 化,只命中本页。本页顶部就是真实导入。
:::

## 启用

功能默认关闭,需要两步(本示例站点已开启,可直接跳到[用法](#usage)):

1. 安装插件(虚拟 css 模块的 resolve/load 由它提供):

```bash
pnpm add -D @10coding/vite-plugin-jsx-scoped
```

2. 在站点配置里打开开关并注册插件:

```ts
// .vitepress-react/config.ts
import jsxScopedVitePlugin from '@10coding/vite-plugin-jsx-scoped'
import { defineConfig } from '@10coding/vitepress-react'

export default defineConfig({
  themeConfig: {
    // 开启 md 页面 scoped 样式
    markdownScopedCss: true
  },
  vite: {
    plugins: [jsxScopedVitePlugin()]
  }
})
```

## 用法 \{#usage\}

**1. 样式放进独立文件。** 文件名以 `.scoped.css`(或 `.scoped.scss` 等)结尾,内容就是普通 CSS,不需要手写任何属性选择器:

```css
/* md-scoped-demo.scoped.css(与本页同目录) */
.md-scoped-card { border: 2px dashed var(--vp-c-brand-2); border-radius: 10px; padding: 0.9rem 1.1rem; background: color-mix(in srgb, var(--vp-c-brand-1) 6%, transparent); }
.md-scoped-card strong { color: var(--vp-c-danger-1); }
```

**2. 在页面模块顶层 import。** 与普通 `import` 一样写在 frontmatter 之后:

```mdx
---
title: 我的页面
---

import './page.scoped.css'

# 我的页面

正文……
```

编译时,`*.scoped.css` 里的每条规则都会被改写为带 `[data-v-{hash}]` 的形式(例如 `.md-scoped-card` → `.md-scoped-card[data-v-6b26034f]`),页面正文由 markdown 编译出的 DOM 元素也自动带上 `data-v-{hash}` 属性——写样式时按普通 CSS 写即可,不需要也不应该自己拼属性选择器。

### 给正文元素加类与锚点 \{#adding-classes-and-anchors\}

页面级 scoped 样式通常配合 **attrs** 给正文元素加类。mdx 内核的 attrs 书写为转义形态 `\{…\}`,作用于元素本身:

| 位置 | 写法 | 作用 |
| --- | --- | --- |
| 标题行尾 | `## 标题 \{#anchor-1\}`、`## 标题 \{.my-cls\}` | 给该标题加 id / class(固定锚点) |
| 块级元素之后独立一行 | `\{.my-card\}` | 作用于**紧邻其前的块**(段落、列表等) |

下一节「实时效果」的卡片段落就是「块后独立 attrs 行」的例子,其源码是

```mdx
**加粗文字**的 danger 色来自……(同样被 scope 化)。

\{.md-scoped-card\}
```

attrs 语法更多说明见[Markdown 中的 React 规则](./md-react-rules#attrs)与[在 Markdown 中使用 React](./using-react)。

## 作用域语义与注意点

- **hash 唯一**:`data-v-{hash}` 由页面文件绝对路径生成,各页各不相同;同一页多个 scoped 文件共用同一 hash;
- **全 DOM 注入**:页面正文编译出的所有元素都会带上 `data-v-{hash}`,因此选择器可以按元素直接写——例如 `.vp-doc p` 只会命中本页的段落;
- **子选择器同样被 scope 化**:`.md-scoped-card strong` 编译为 `.md-scoped-card strong[data-v-{hash}]`,命中卡片内的后代 `strong`(后代元素自身也带属性);
- **样式文件只归一个页面**:同一个 `*.scoped.css` 只能被一个页面 import,跨页面共享会在构建时报错;需要多页复用的样式请放进全局 css;
- **失败降级**:极少数语法边界导致页面代码无法解析时,管线会告警并跳过 scoped 处理,页面照常编译。

## 检查方式

::: details 检查方式
- **dev**:打开本页,元素检查可见正文 DOM 带 `data-v-xxxxxxxx` 属性,样式规则形如 `.md-scoped-card[data-v-xxxxxxxx]`;
- **build**:产物 html 同样带 `data-v-xxxxxxxx`,对应 css 资源里选择器形如 `.md-scoped-card[data-v-xxxxxxxx]`,且该 css 仅由本页引入。
:::
